# ProtectedDemo

Минимальный C++20-стенд для первого запуска. Он не изменяет другие процессы:
программа создаёт собственный тестовый буфер, сохраняет его контрольную сумму,
потом намеренно изменяет один байт и фиксирует событие в `security_audit.log`.

## Открытие в Visual Studio

1. Открой `ProtectedDemo.sln` двойным щелчком.
2. В верхней панели выбери `x64` и `Debug`.
3. Нажми `Ctrl+F5` (запуск без отладки) — это режим самотеста.
4. В папке `build\\Debug` появятся `ProtectedDemo.exe` и `security_audit.log`.

Ожидаемый результат: `Result: modification detected`.

## Режим без модификации

Для проверки отсутствия ложных срабатываний открой свойства проекта,
перейди в `Configuration Properties → Debugging → Command Arguments` и введи
`--normal`. После `Ctrl+F5` программа три секунды мониторит неизменяемую
область памяти. Ожидаемый результат: `Result: no modification and no false alarm.`

## Серия измерений

Перед серией закрой приложение и в `Command Arguments` введи `--benchmark`.
Программа проведёт по 5 самотестов для интервалов 100, 250, 500 и 1000 мс,
а результаты сохранит в `benchmark_results.csv` рядом с исполняемым файлом.
Это исходные измерения: в пояснительной записке следует указывать число повторов,
среднее значение и условия проведения эксперимента.

## Тест стабильности

Укажи `--stability` в `Command Arguments`. Программа выполнит 40 запусков
без модификации памяти: по 10 для каждого интервала. Итоговая строка покажет
число фактически выполненных проверок и FPR; сырые результаты будут записаны
в `stability_results.csv` рядом с исполняемым файлом.

## Контроль исполняемого кода

Укажи `--module-check` в `Command Arguments`. Программа найдёт `.text`-секцию
собственного EXE по структурам PE, построит её контрольную сумму и три секунды
будет контролировать неизменность этой секции. Режим не модифицирует память и
не взаимодействует с другими процессами.

## Самотест атрибутов памяти

Укажи `--protection-self-test` в `Command Arguments`. Программа выделит
собственную тестовую страницу, запомнит её атрибут PAGE_READWRITE и изменит
атрибут на PAGE_READONLY. Изменение должно быть обнаружено через VirtualQuery.

## Измерение ресурсов

Укажи `--performance` в `Command Arguments`. Программа пять раз по десять
секунды измерит потребление ресурсов: один раз в базовом режиме без монитора
и по одному разу с мониторингом `.text` при интервалах 100, 250, 500 и 1000 мс.
В `performance_results.csv` будут сохранены CPU процесса, рабочий набор и
private memory. Значения относятся к текущему процессу и служат для сравнения
базового и контролируемого режимов.

## Дополнительные эксперименты для курсового проекта

Все режимы ниже выполняются только внутри текущего процесса. Они не открывают,
не изменяют и не внедряются в другие приложения.

### Длительная проверка стабильности

Укажи `--extended-stability 120` для двухчасового теста. Число минут можно
менять, например `--extended-stability 180` для трёх часов. Контролируется
неизменяемая область 32 МиБ с интервалом 500 мс. Раз в секунду снимается
потребление CPU; в `extended_stability_results.csv` сохраняются число проверок,
ложные срабатывания, среднее, медиана и стандартное отклонение CPU.

Для быстрой проверки перед длительным запуском можно указать
`--extended-stability 3`.

### Проверка под нагрузкой

Укажи `--load-test`. Стенд сравнит режимы простоя и контролируемой нагрузки
внутри собственного процесса для интервалов 50 и 500 мс. Контролируемая область
имеет размер 32 МиБ; рабочий поток изменяет отдельный буфер и не касается
защищаемой области. Итоги сохраняются в `load_test_results.csv`.

### Зависимость от размера области и интервала

Укажи `--scalability`. Стенд последовательно проверяет области 1, 100 и
1024 МиБ при интервалах 50, 100, 250 и 500 мс. Для каждой комбинации он
сохраняет загрузку CPU, число проверок и среднее время расчёта хеша в
`scalability_results.csv`. Вариант 1024 МиБ автоматически пропускается,
если свободной физической памяти недостаточно: это будет явно отмечено в CSV,
а не заменено вымышленным измерением.

### Ограничение периодической проверки (TOCTOU)

Укажи `--toctou`. Программа двадцать раз для каждого интервала кратковременно
изменяет и восстанавливает байт собственной атомарной тестовой области.
`toctou_results.csv` показывает, какие кратковременные изменения были замечены,
а какие прошли внутри окна между проверками. Это эксперимент по ограничению
метода периодического опроса, а не тестирование внешнего вмешательства.

## Что нужно понять перед следующим этапом

- `testRegion` — тестируемая область памяти.
- `Start()` считает её исходную контрольную сумму и запускает фоновый поток.
- `Monitor()` пересчитывает сумму каждые 100 мс.
- При расхождении создаётся запись в журнале и фиксируется инцидент.
